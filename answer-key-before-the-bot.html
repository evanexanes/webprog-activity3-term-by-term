Compute the answer key before you build the bot

RPASYST · Year 2, Term 1 · 2 min read

Based on: RPASYST Final, XYZ Invoice Processing, checked 2026-10-05

The RPASYST final asked for a bot that processes vendor invoices from an Excel file. It had to be built in Power Automate Desktop only, with no VBA, Python, PowerShell or third-party tools inside the bot. I built it at home on a Windows machine and presented it live on checking day, explaining every action out loud.

The sample is not the brief

The brief said 250 rows. The sample had 249 plus a header, with one record already moved to an Invalid Records sheet, and the file used on checking day had 3,000 rows. The midterm had the same gap: the brief said 20 rows and the sample had 65. So I worked out the expected results from the raw file before building anything.

An answer key from outside the bot

Python could not go inside the bot, but nothing stopped me using it to check one. I calculated the expected totals in a separate script, so the bot had something to be compared against. That also exposed a problem the sample hid: row 11 was completely blank, a record cut out and the row left behind. It crashed the first run until I wrapped the loop in an IsNotEmpty check on the vendor.

Three smaller fixes

  • Read the Excel file as typed values, never as text, so a negative amount stays a number. Round with Text.FromNumber and then Text.ToNumber to remove float noise such as -97091.00000001.
  • The designer's Run delay was 50 ms. Looping all rows once per vendor is about 36,000 passes at 3,000 rows, and at 50 ms the sample alone took about seven minutes. Set it to 0 and run from the console.
  • Launch Excel with Visible set to True. A workbook saved from a hidden window reopened blank and dark.

Next time

List every gap in the brief (sheet names, what makes a record invalid) as an assumption, and ask before building.
