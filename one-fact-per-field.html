One fact per field, one fact per row

ANLYTC1 · Year 2, Term 2 · 2 min read

Based on: ANLYTC1 Data Cleansing Exercises, Data2 to Data6, submitted 2026-11-06

The ANLYTC1 cleansing exercises gave me five messy workbooks. Every one of them broke the same rule: one fact per field, one fact per row. Once I saw that, each file was a question of which half of the rule it broke.

The five dirt patterns and their fixes
PatternLooks likeFix
CrosstabShip Mode spread over 12 columnsOne row per value: loop over the columns and write one row for each
Run-on textName X Address Y Age 17 Gender Male in one cellOne pattern that uses the labels as separators
Fused fields0Bottle, a quantity and a unit in one cellNumber up front into a numeric column, letters at the back
Letters typed for digits41oo, I000, 0.SA character map (o to 0, i to 1, s to 5), then prove it row by row
Packed cellsBinders | Art | Phones beside three pricesSplit both cells, pair by position, repeat the key. This is 1NF

Proving the letter map

A substitution map can look right and still be wrong. The inventory sheet had Beginning + Received - Dispensed - Losses = Ending on every row, so I used that arithmetic to confirm each guess, row by row.

A total that did not match

Four of the five totals on Data5 matched the answer key. Quantity Received did not: I had 250,997.30 and the key had 250,992.00. The 5.30 difference was exactly the 14 fractional cells (4.8) plus the 0.S cell (0.5). The key left fractions out of that column and counted them in the other three. I reported the difference instead of changing the data to hit the number.

Next time

Verify with a separate script from the one that did the cleaning. Compare sample rows, row counts and totals, then reopen the file in a second program.
